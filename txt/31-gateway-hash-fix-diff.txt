    Thread file content hash through the gateway extractor
    
    An interpreter-launched local MCP server mirrored by the gateway carries the
    script's content digest under metadata.fileContentHash. The gateway extractor
    never read it, so the shared writer derived version=unknown and forked a second
    asset row instead of converging on the scanner row for the identical launch.
    
    Read fileContentHash into McpServerInput.file_content_hash exactly as the
    scanner extractor does, so both lanes feed the same shared
    resolve_mcp_local_version and compose the same content-digest version. The
    name-based app-definition id (and its guard mirror) is unaffected.

# The four tables the MCP write chain touches are each protected by a MATCHED PAIR: a Python-side
# INSERT ... ON CONFLICT upsert whose index_elements name the conflict target, and a DB-level UNIQUE
# index of the same name created in a corpus migration. A replayed payload re-derives the same keys,
# so each layer's ON CONFLICT turns the second write into an update-or-noop -> no duplicate rows.
# "Shown enforced": passes A1 (re-upload) and B (genuine SQS redelivery) both produced a BYTE-IDENTICAL
# content snapshot (see 20-replay-after.txt) — the constraints below are what forced that.
